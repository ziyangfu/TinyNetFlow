中间件开发的核心难点是什么？该中间件的核心难点是什么？
基于对 TinyNetFlow 项目的深入分析，该车载通信中间件的核心难点主要体现在以下几个方面：

1. 车载领域的实时性和确定性要求
   TinyNetFlow 专为车载领域设计，具有高度安全敏感（功能安全、信息安全）、实时敏感（确定性通信与确定性调度）的特殊性 README.md:38-39 。项目计划在 V4.0 版本实现执行管理与确定性调度，包括用户空间的执行管理和深入内核的确定性调度策略，调整内核调度器策略，考虑增加时间触发机制 README.md:40-42 。

2. 复杂的网络架构和性能优化
   中间件采用 Reactor 网络模型与 epoll IO多路复用机制 README.md:4-8 ，需要处理复杂的事件循环管理，包括原子操作控制、多线程同步、唤醒机制等 EventLoop.h:44-62 。项目计划在 V3.0 版本使用 XDP/DPDK 等 kernel bypass 技术，聚焦实时性、确定性延迟等方向，优化网络性能 README.md:36 。

3. 资源隔离和进程管理
   使用 Linux Cgroups V2 进行资源控制管理，需要处理 CPU 限制、内存限制、CPU 核绑定等复杂配置 CGroupV2Controller.h:1-23 。还需要支持多种调度策略和进程设置，包括调度策略、调度优先级、CPU 亲和性等 ProcessSetting.h:26-34 。

4. 服务发现机制的复杂性
   实现跨端跨设备的发现功能，需要处理统一设备标识、混合网络发现（局域网基于 mDNS/DNS-SD 协议，广域网通过云服务同步），并要求发现时延控制在 100ms 以内 README.md:4-38 。

5. 安全性要求
   项目计划采用 AUTOSAR C++14 标准，朝功能安全与信息安全方向靠近 README.md:31 。在存储模块需要实现加密存储和 CRC 完整性校验 README.md:27-28 。

6. 时间同步的技术挑战
   需要解决网络时间同步问题，特别是在蜂窝网络环境下存在 4-10 毫秒抖动的情况下实现高精度时间同步，要求能够提供微秒级精度的时间戳 README.md:81-84 。

7. 全链路可观测性
   使用 eBPF 技术实现从内核空间到用户空间的全链路数据观测、诊断与优化，在中间件的多个关键节点写入静态的 USDT（Userland Statically Defined Tracepoints）进行跟踪 BpfTrace.h:1-16 。

8. 模块化架构设计
   项目包含多个复杂模块：操作系统适配层（osadaptor）、通信模块（com）、执行管理（em）、计算模块（compute）、OTA、持久化（per）、安全（safety）、时间同步（tsync）等 project_compile_options.json:3-66 ，各模块之间的协调和接口设计是重要挑战。

前面三个静态链接库，使用了spdlog， 并且是以head_only的方式引入，而libper暂未
引入spdlog，什么都不变，仅进入spdlog，则大小变为10MB。因此编译出来的静态链接库太大的原因就在于spdlog
